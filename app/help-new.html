Getting Started with CaddyMAN

CaddyMAN is a web-based management interface for Caddy Server with built-in Identity & Access Management (IAM) features.

Quick Start

  1. Default Login: Username admin, Password changeme (you'll be forced to change on first login)
  2. Access: http://localhost:8000 (default manager port)
  3. Dashboard: View Caddy status, proxies, websites, users, and pending invitations
  4. Configuration: All settings stored in CaddyMAN.db (SQLite database)

Key Concepts

  • Reverse Proxies: Forward requests to backend services (e.g., apps running on different ports)
  • Static Websites: Serve HTML/PHP sites from local directories
  • Auto HTTPS: Automatic TLS certificates via Let's Encrypt (requires port 80 + valid domain)
  • Access Groups: Restrict proxies/websites to authenticated users in specific groups
  • SSO: Single session across admin panel, LDAP, OIDC, and protected websites

Reverse Proxies

Forward incoming requests to backend services running on different ports or servers.

Basic Configuration

  1. Domains: Enter one or more domain names (e.g., api.mydomain.com) - one per line
  2. Target: Backend URL (e.g., http://localhost:3000 or http://192.168.1.100:8080)
  3. HTTP Ports: Port 80 (default) or custom ports like 8080 - one per line
  4. HTTPS Ports: Port 443 (default) or custom ports like 8443 - one per line
  5. Auto HTTPS: Enable for automatic TLS certificates (requires port 80 for HTTP-01 challenge)
  6. Access Groups: Require authentication from users in selected groups (optional)

Advanced Features

  • WebSocket Support: Enable for services using WebSockets (e.g., HomeAssistant)
  • Custom Headers: Add headers to proxied requests (JSON format: {"X-Custom": "value"})
  • Load Balancing: Distribute requests across multiple backend servers
  • Additional Directives: Add raw Caddyfile text for custom configurations

Advanced JSON Mode

For complex configurations, use Advanced JSON mode to define custom Caddy routing. Example: Media server with optimized streaming.

{
  "routes": [
    {
      "match": [
        {
          "host": ["media.mydomain.com"],
          "path": [
            "/Videos/*",
            "/Audio/*",
            "/Items/*",
            "/socket*"
          ]
        }
      ],
      "handle": [
        {
          "handler": "reverse_proxy",
          "upstreams": [{"dial": "127.0.0.1:8096"}],
          "flush_interval": -1,
          "headers": {
            "request": {
              "set": {
                "X-Forwarded-Proto": ["https"],
                "X-Real-IP": ["{http.request.remote}"]
              }
            }
          }
        }
      ]
    },
    {
      "match": [{"host": ["media.mydomain.com"]}],
      "handle": [
        {
          "handler": "encode",
          "encodings": {"gzip": {}, "zstd": {}},
          "prefer": ["gzip"]
        },
        {
          "handler": "reverse_proxy",
          "upstreams": [{"dial": "127.0.0.1:8096"}]
        }
      ]
    }
  ]
}

Key Points:

  • Port Configuration: Set HTTPS/HTTP ports in form fields above JSON (defaults to 443 if empty)
  • No Server Definition: Don't include "servers" or "listen" - CaddyMAN handles this
  • Routes Order: More specific routes (with path matchers) should come first
  • flush_interval: -1 - Disables buffering for streaming/SSE
  • encode handler - Compresses non-streaming responses

Full documentation: Caddy JSON Structure

Static Websites

Serve HTML, CSS, JavaScript, and PHP files from local directories.

Configuration

  1. Domains: Domain names or IP addresses - one per line
  2. Root Path: Absolute path to website files (must be at least one subfolder deep for security)
  3. Index Files: Default files (e.g., index.html, index.php) - one per line
  4. HTTP/HTTPS Ports: Same as reverse proxies
  5. PHP Enabled: Check to enable PHP support (requires global PHP configuration)
  6. Auto HTTPS: Enable for automatic TLS certificates
  7. Access Groups: Restrict to authenticated users

PHP Support

Enable PHP globally in Settings:

  • PHP Enabled: Master switch in Settings
  • PHP-CGI Path: Path to php-cgi executable (e.g., C:\php\php-cgi.exe or /usr/bin/php-cgi)
  • Per-Site: Enable PHP checkbox on individual websites
  • Default Port: PHP-CGI runs on port 9000 (automatic)

Security

Important: Website root must be at least one subfolder deep to prevent exposing CaddyMAN.db and other sensitive files.

  • ✅ Safe: www, public, sites/mysite
  • ❌ Blocked: Current directory, parent directories

Identity & Access Management (IAM)

CaddyMAN provides enterprise-grade authentication for modern and legacy applications.

LDAP Server

  • Purpose: Authenticate legacy apps (Emby, Jellyfin, etc.)
  • Port: Configurable (default 389 conflicts on Windows - use 3389 or another port)
  • Binding: Automatically listens on all interfaces (0.0.0.0)
  • Security: External/public IPs automatically rejected - only private networks allowed
  • Allowed Groups: Restrict LDAP access to specific user groups
  • Enhanced Security Mode: Requires users to append 6-digit 2FA code to password (password123456)
  • Admin Block: Admin users cannot authenticate via LDAP (security)

RADIUS Server

  • Purpose: WiFi WPA2-Enterprise authentication
  • Auth Port: 1812 (configurable)
  • Accounting Port: 1813 (configurable)
  • EAP Methods: PAP, PEAP (MSCHAPv2), EAP-TTLS (PAP) - configurable
  • WiFi Passwords: Users can set separate WiFi password in User Portal (PEAP only)
  • Security: Same external IP blocking as LDAP
  • VLAN Assignment: Optional VLAN assignment support

OIDC/OAuth2 Provider

  • Purpose: Modern app authentication (Audiobookshelf, Grafana, etc.)
  • Issuer URL: Your domain (e.g., https://auth.mydomain.com)
  • Endpoints: /.well-known/openid-configuration, /oauth/authorize, /oauth/token, /oauth/userinfo
  • Flows: Authorization code with PKCE, refresh tokens
  • Scopes: openid, profile, email, groups, custom claims
  • Client Management: Create OAuth clients with redirect URIs and group restrictions

Two-Factor Authentication (2FA)

  • Per-User: Users enable TOTP in User Portal (/user-portal)
  • Force 2FA: Require 2FA for users in specific groups (blocks access until configured)
  • Enhanced Security Mode: Enforces 2FA for all admin and LDAP logins
  • Setup: Scan QR code with authenticator app (Google Authenticator, Authy, etc.)

User Management

  • Invite System: Send email invites with time-limited tokens (1-720 hours)
  • Password Reset: Email-based password reset with 2FA verification
  • User Portal: /user-portal - change password, email, 2FA, WiFi password
  • Groups: Assign users to groups for access control
  • Password Security: Argon2id hashing with DPAPI-encrypted pepper (Windows)

Settings

SMTP Configuration

  • Required For: Invite links, password resets, notifications
  • Settings: Server, port (587 default), TLS, username, password
  • Test: Use "Test Email" button to verify configuration
  • Security: Password encrypted with DPAPI-derived key

Notifications

  • Services: Gotify, Ntfy
  • Event Types: 50+ events (security alerts, system events, user actions, etc.)
  • Granular Control: Enable/disable individual events with severity levels
  • Auto-Retry: 3 attempts with 15-second delays for delivery reliability

Logging

  • Caddy Log Level: DEBUG, INFO, WARN, ERROR (requires Caddy restart)
  • CaddyMAN Log Level: Tied to Caddy level (applies immediately)
  • Log Files: app.log (CaddyMAN), check Caddy admin endpoint for Caddy logs

Other Settings

  • Manager Port: Port for admin interface (default 8000)
  • Domain URL: Your main domain for SSO cookie scope and invite links
  • Enhanced Security: Enforces 2FA on admin/LDAP, blocks user creation without 2FA
  • Organization Name: Branding for emails and UI

Troubleshooting

Caddy Won't Start

  • Port Conflicts: Use netstat -ano | findstr :PORT to check if port is in use
  • Configuration Error: Check Caddy logs for syntax errors in Advanced JSON or directives
  • Permissions: Ensure Caddy can bind to ports (especially 80/443)
  • Path Issues: Verify Caddy executable path in Settings is correct

PHP Not Working

  • Global Enable: Ensure PHP is enabled in Settings
  • PHP-CGI Path: Verify path to php-cgi executable
  • Site Enable: Check PHP checkbox on website
  • Port Conflict: Ensure port 9000 is available
  • Restart: Restart Caddy after changing PHP settings

Auto HTTPS Not Working

  • Port 80 Required: Must be available for HTTP-01 challenges
  • Valid Domain: Need real domain pointing to your server (not localhost or IP)
  • DNS Propagation: Ensure DNS records have propagated
  • Firewall: Ports 80 and 443 must be open
  • Alternative: Use custom TLS with your own certificates

LDAP/RADIUS Connection Issues

  • Network Binding: Servers automatically bind to all interfaces (0.0.0.0)
  • Allowed Networks: Only private IPs (10.x, 172.16-31.x, 192.168.x, localhost)
  • External IPs Blocked: Public IPs automatically rejected with security notifications
  • Startup Logs: Verify "LDAP server listening on 0.0.0.0:PORT" message
  • Port Conflicts: Use netstat -an | findstr :389 (LDAP) or netstat -an | findstr :1812 (RADIUS)
  • Firewall: Ensure Windows Firewall allows inbound connections
  • Group Filtering: Verify user is in allowed groups

Session Expired / Can't Login

  • Session Duration: Sessions expire after 7 days
  • Clear Cookies: Try clearing browser cookies for CaddyMAN
  • CSRF Errors: Refresh the page to get a new CSRF token
  • 2FA Required: If in force-2FA group, must enable 2FA in User Portal first

API Reference

CaddyMAN provides a REST API for automation. All endpoints require session authentication via session_id cookie.

CSRF Protection

All POST/PUT/DELETE requests require X-CSRF-Token header. Get token from login response:

POST /api/login
{"username": "admin", "password": "your_password"}

Response: {"csrf_token": "xxx", "username": "admin", ...}

Key Endpoints

  • POST /api/login - Authenticate (returns CSRF token)
  • POST /api/auth/logout - End session
  • GET /api/settings - Get all settings
  • POST /api/settings - Update settings (requires CSRF)
  • GET /api/proxies - List reverse proxies
  • POST /api/proxies - Create/update proxy (requires CSRF)
  • GET /api/websites - List websites
  • POST /api/websites - Create/update website (requires CSRF)
  • GET /api/users - List users
  • POST /api/users - Create user (requires CSRF)
  • GET /api/groups - List groups
  • GET /api/caddy/status - Check Caddy status
  • POST /api/caddy/restart - Restart Caddy (requires CSRF)
  • GET /api/status/stream - SSE endpoint for real-time updates

Full API Documentation: Available at /docs when log level is set to DEBUG (shows warning banner)

Database & Backups

CaddyMAN uses SQLite for reliable, file-based data storage.

Database File

  • Location: CaddyMAN.db (same directory as executable)
  • Contains: Users, groups, proxies, websites, settings, invites, blocked IPs
  • Encryption: Sensitive fields encrypted with DPAPI-derived keys (Windows)

Backup

  • Simple: Just copy CaddyMAN.db to a safe location
  • Restore: Stop CaddyMAN, replace database file, restart
  • Security Note: Moving database to different machine invalidates DPAPI-encrypted secrets (passwords, tokens)
  • Also Backup: pepper.enc (required for password verification)

Version Management

  • Minimum Version: v1.3.17 requires database from v1.3.16 or newer
  • Downgrades: Allowed as long as version meets database's minimum requirement
  • Tracking: Database stores last version used and minimum version required
