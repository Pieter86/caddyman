Help & Documentation

Getting Started

CaddyMAN is a powerful web-based management interface for Caddy web server v2. It provides an intuitive GUI to manage reverse proxies, static websites, user authentication, and more.

First Time Setup

  1. Login: Default credentials are username: admin, password: changeme
  2. Change Password: You will be prompted to change the default password on first login (required for security)
  3. Enable 2FA: For enhanced security, enable Two-Factor Authentication in the Users page
  4. Configure Settings: Visit the Settings page to configure PHP, ports, and other options

Security Features

  • CSRF Protection: All state-changing requests are protected against cross-site request forgery
  • Rate Limiting: 5 failed login attempts result in a 15-minute account lockout
  • Secure Sessions: Cryptographically secure session IDs with SameSite cookie protection
  • Password Security: Enhanced mode checks passwords against known breaches (HIBP)

Dashboard

The dashboard provides an overview of your Caddy server status and quick statistics:

  • Caddy Status: Shows if Caddy is running or stopped with the current process ID
  • Statistics: Total count of reverse proxies, websites, users, and groups
  • Updates: Shows current version (v1.2.23) and checks for available updates

Reverse Proxies

Reverse proxies forward incoming requests to backend services running on different ports or servers.

Creating a Reverse Proxy

  1. Click the "Add Reverse Proxy" button
  2. Domains: Enter domain names (e.g., api.example.com) - one per line
  3. Target: Enter the backend URL (e.g., http://localhost:3000)
  4. Ports: Configure HTTP ports (e.g., 80, 8080) and HTTPS ports (e.g., 443, 8443)
  5. Auto HTTPS: Enable for automatic TLS certificate management (requires port 80 available)
  6. Access Groups: Restrict access to specific user groups (optional)
  7. Advanced: Add custom Caddyfile directives for complex configurations

Important Notes

  • Port 80 Requirement: Auto HTTPS only works when port 80 is available for HTTP challenges
  • Custom HTTPS: When using non-standard HTTPS ports, Auto HTTPS is automatically disabled
  • Multiple Domains: You can serve multiple domains from one reverse proxy configuration

Static Websites

Host static websites and PHP applications directly from local directories.

Creating a Website

  1. Click the "Add Website" button
  2. Domains: Enter domain names or use IP addresses - one per line
  3. Root Path: Absolute path to the website files (e.g., C:\inetpub\wwwroot\mysite)
  4. Index Files: Default files to serve (e.g., index.html, index.php) - one per line
  5. Ports: Configure HTTP and HTTPS ports
  6. PHP Enabled: Enable if the site contains PHP files (requires PHP configuration in Settings)
  7. Auto HTTPS: Enable for automatic TLS (requires port 80 and valid domain)
  8. Access Groups: Restrict access to authenticated users in specific groups

PHP Configuration

  • Requirements: PHP-CGI must be installed and path configured in Settings
  • Global Enable: PHP must be enabled globally in Settings for per-site PHP to work
  • FastCGI: CaddyMAN automatically starts PHP-CGI on the configured port (default: 9000)
  • Extensions: Only files with extensions listed in Settings will be processed as PHP

Users & Groups

User Management

Control who can access protected websites and reverse proxies:

  • Create Users: Add users with usernames, secure passwords, and email addresses
  • Assign Groups: Users can belong to multiple groups for access control
  • Two-Factor Auth: Enable 2FA per user for enhanced security
  • Password Requirements: Minimum 4 characters (always enforced); enhanced mode adds complexity requirements
  • Invite Links (v1.3.1): Generate invite links to onboard new users via email (visible when SMTP is configured)

Group Management

  • Access Control: Groups define which users can access specific sites/proxies
  • System Groups: Some groups (like admin_group) are protected and cannot be deleted
  • Multiple Groups: Assign sites to multiple groups for flexible access control
  • Force 2FA (v1.3.1): Require all users in a group to enable 2FA before accessing admin panel, LDAP, or OIDC

Two-Factor Authentication (2FA)

  1. Click "Show QR Code" next to a user
  2. Scan the QR code with an authenticator app (Google Authenticator, Authy, etc.)
  3. Enable 2FA for that user
  4. User will need to enter TOTP code after password on login

User Self-Service Portal (v1.3.1)

Users can manage their own accounts at /user-portal:

  • Change Password: Users can change their password (requires current password for security)
  • Update Email: Users can update their email address
  • Manage 2FA: Users can enable/disable 2FA and view QR codes
  • Password Reset: "Forgot Password" link allows reset via email (requires SMTP configuration)
  • Account Setup: New users invited via invite links can set their password here

Invite Link System (v1.3.1)

Streamline user onboarding with secure invite links:

  1. Click "Generate Invite Link" in Users page (requires SMTP configuration)
  2. Enter username, email, groups, and link expiry time (1-720 hours)
  3. System sends email with invite link to the user
  4. User clicks link and sets their password at /user-portal
  5. Invite link is single-use and expires after the specified time

Security: Admin-only feature, prevents creation of admin users via invites, cryptographically secure tokens

Authentication & Single Sign-On (v1.3.0+)

CaddyMAN provides comprehensive Identity & Access Management (IAM) features with unified Single Sign-On (SSO).

Single Sign-On (SSO)

One Login, Access Everything: When you log into CaddyMAN, you're automatically authenticated for:

  • ✅ All protected websites
  • ✅ All protected reverse proxies
  • ✅ All OAuth/OIDC applications (Audiobookshelf, etc.)
  • ✅ No need to log in multiple times!

OAuth/OIDC Provider

Create OAuth clients for modern applications to authenticate with CaddyMAN:

  • Supported Apps: Audiobookshelf, Jellyfin, Home Assistant, and any OIDC-compatible app
  • Group-Based Access: Restrict each OAuth client to specific user groups (v1.3.1+)
  • Custom Claims (v1.3.6): Configure application-specific permissions per group via JSON (e.g., AudiobookShelf permissions, Jellyfin profiles, Grafana roles) - only visible when OIDC is enabled
  • Security: PKCE required, JWT with replay prevention, admin users blocked
  • Configuration: Get Client ID & Secret when creating client (save secret immediately!)

OIDC Custom Claims (v1.3.6)

Configure application-specific permissions and settings that are automatically included in OIDC UserInfo responses:

  • Per-Group Configuration: Edit any group and paste JSON with custom claims (only when OIDC is enabled)
  • Automatic Merging: Claims from all user's groups are merged into the UserInfo response alongside standard claims (email, name, groups)
  • AudiobookShelf Support: Configure permissions like canDownload, canUpload, allowedLibraries, etc.
  • Multi-App Support: Include claims for multiple apps in one group (Jellyfin, Grafana, etc.)
  • Example: {"abspermissions": {"canDownload": true, "canUpload": false}, "grafana_role": "Editor"}
  • Validation: JSON syntax is validated before saving to prevent errors

LDAP Server

Authenticate legacy applications that support LDAP:

  • Port: Default 389 (configurable)
  • Base DN: Your LDAP base (e.g., dc=example,dc=com)
  • Bind DN: Admin bind DN (e.g., cn=admin,dc=example,dc=com)
  • Group Filtering: Restrict LDAP access to specific user groups (v1.3.1+)
  • Security: Rate limiting, admin users blocked from LDAP access

RADIUS Server (WiFi WPA2-Enterprise)

Secure your WiFi network with user-based authentication:

  • Authentication Port: Default 1812
  • Accounting Port: Default 1813
  • Shared Secret: 512-bit random secret (use Generate button) - configure on both RADIUS server and WiFi access point
  • EAP Methods:
    • EAP-TTLS: Most secure with PAP inner authentication (recommended)
    • PEAP: Compatible with Windows and enterprise devices using MSCHAPv2
    • PAP: Simple but insecure (passwords sent over network, no TLS)
  • Router Support: Works with ASUS routers and most WPA2/WPA3-Enterprise capable access points
  • VLAN Assignment: Dynamically assign VLANs based on user groups
  • Group Filtering: Control WiFi access by user groups (v1.3.1+)
  • Security: Rate limiting, admin users blocked from RADIUS access

SMTP/Email System (v1.3.1)

  • User Invites: Send invitation emails with secure setup links (1-720 hour expiry)
  • Password Resets: Email password reset links to users (1 hour expiry, 2FA verification if enabled)
  • Configuration: SMTP server, port, TLS, authentication credentials
  • Security: All tokens are cryptographically secure, single-use, and time-limited

Group-Based Access Control (v1.3.1+)

Fine-grained control over who can access each authentication method:

  • OAuth Clients: Create group "audiobookshelf-users", only they can sign into that app
  • LDAP: Create group "ldap-users", only they can authenticate via LDAP
  • RADIUS: Create group "wifi-staff", only they can connect to WiFi
  • Websites/Proxies: Each site/proxy can require specific groups
  • Empty = Allow All: If no groups selected, all users can access (backward compatible)

Settings

Configure global application behavior and Caddy server options.

Application Settings

  • Theme: Choose between Dark mode (default), Light mode, or Black mode
  • Manager Port: Port for CaddyMAN web interface (default: 8000)
  • Caddy Admin Port: Port for Caddy's admin API (default: 12999, requires Caddy restart)
  • Enhanced Security Mode: Requires authentication on management interface, enables 2FA option
  • Enable Authentication Protocols: Master switch to enable/disable the Authentication page with IAM features (v1.3.0+)

PHP Settings

  • Enable PHP: Master switch - must be ON for any site to use PHP
  • PHP Path: Full path to php-cgi executable
  • PHP Port: FastCGI port for PHP processing (default: 9000)
  • PHP Extensions: File extensions to process as PHP (e.g., .php, .phtml)

Caddy Settings

  • Caddy Path: Path to Caddy v2 executable
  • Config Path: Where Caddy configuration is saved
  • Log Level: Verbosity of Caddy logs (DEBUG, INFO, WARN, ERROR)

Enhanced Security Mode

  • Purpose: Adds extra security by requiring authentication on the management interface itself
  • When Enabled: All API requests require valid authentication token
  • Login Required: Must log in before accessing any page
  • Best Practice: Enable for production environments

Notifications

  • Gotify: Receive notifications via Gotify (self-hosted notification service)
  • Ntfy: Send notifications to Ntfy (https://ntfy.sh or self-hosted)
  • Events: Get notified on Caddy restarts, configuration changes, and updates

Advanced Features

Custom Caddyfile Directives

Use the "Advanced" field in reverse proxies and websites to add custom Caddyfile directives:

header {
    # Security headers
    X-Frame-Options "DENY"
    X-Content-Type-Options "nosniff"
}

# Rate limiting
rate_limit {
    zone static {
        key {remote_host}
        events 100
        window 1m
    }
}

Manual TLS Configuration

For custom SSL certificates, use the TLS field in advanced settings:

tls /path/to/cert.pem /path/to/key.pem

Multiple Ports

Sites and proxies can listen on multiple HTTP and HTTPS ports simultaneously. Just add each port on a new line in the ports configuration.

Troubleshooting

Caddy Won't Start

  • Port Conflicts: Check if another service is using the configured ports (use netstat -ano | findstr :PORT)
  • Configuration Error: Check the Caddy logs for syntax errors in advanced directives
  • Permissions: Ensure Caddy has permission to bind to ports (especially 80/443)
  • Path Issues: Verify the Caddy executable path in Settings is correct

PHP Not Working

  • Global Enable: Ensure PHP is enabled globally in Settings
  • Site Enable: Ensure the specific website has PHP enabled
  • PHP Path: Verify the path to php-cgi is correct in Settings
  • Port Conflict: Check if another service is using the PHP FastCGI port (default: 9000)
  • Restart Required: Restart Caddy after changing PHP settings

Auto HTTPS Issues

  • Port 80 Required: Auto HTTPS needs port 80 available for HTTP-01 challenges
  • Valid Domain: You need a real domain name that points to your server (not localhost or IP)
  • DNS Propagation: Ensure DNS records have propagated before attempting HTTPS
  • Firewall: Ports 80 and 443 must be open in your firewall
  • Alternative: For local development, use custom TLS or disable HTTPS

Settings Not Persisting

  • Fixed in v1.2.11: Settings now properly persist across restarts
  • Database: All configuration is stored in CaddyMAN.db (SQLite)
  • Backup: Back up CaddyMAN.db regularly to preserve your configuration

Can't Access Management Interface

  • Port Check: Verify CaddyMAN is running on the configured port (default: 8000)
  • URL: Access via http://localhost:8000 or http://127.0.0.1:8000
  • Process Check: Run tasklist | findstr python to verify the process is running
  • Logs: Check app.log for startup errors

Invite Links / Password Reset Not Working (v1.3.1)

  • SMTP Configuration: Ensure SMTP is enabled and properly configured in Settings
  • Email Credentials: Verify SMTP username and password are correct
  • Port & TLS: Check SMTP port (usually 587 for TLS, 465 for SSL) and TLS setting
  • Firewall: Ensure outbound SMTP connections are allowed
  • Spam Folder: Check user's spam/junk folder for invite/reset emails
  • Token Expiry: Invite links expire after configured time (1-720 hours), reset links expire after 1 hour

Force 2FA Issues (v1.3.1)

  • Access Blocked: If user is in a force-2FA group but hasn't set up 2FA, they're blocked from admin/LDAP/OIDC
  • Solution: User should visit /user-portal to enable 2FA (portal access is NOT blocked)
  • Check Groups: Verify which groups have force_2fa enabled in group settings
  • Service Accounts: LDAP bind DN users bypass force-2FA requirement

API Endpoints

CaddyMAN provides a REST API for automation and integration:

Authentication

  • POST /api/auth/login - Authenticate and receive session token + CSRF token
  • POST /api/auth/logout - End current session
  • GET /api/auth/me - Get current user info

Caddy Control

  • GET /api/caddy/status - Check Caddy running status
  • POST /api/caddy/start - Start Caddy server
  • POST /api/caddy/stop - Stop Caddy server
  • POST /api/caddy/restart - Restart Caddy server
  • GET /api/caddy/config - View current Caddy configuration

Configuration Management

  • GET /api/proxies - List all reverse proxies
  • POST /api/proxies - Create/update reverse proxy (requires X-CSRF-Token header)
  • DELETE /api/proxies/{id} - Delete reverse proxy (requires X-CSRF-Token header)
  • GET /api/websites - List all websites
  • POST /api/websites - Create/update website (requires X-CSRF-Token header)
  • DELETE /api/websites/{id} - Delete website (requires X-CSRF-Token header)
  • GET /api/users - List all users
  • GET /api/groups - List all groups
  • GET /api/settings - Get all settings
  • POST /api/settings - Update settings (requires X-CSRF-Token header)

CSRF Protection

All POST, PUT, and DELETE requests require an X-CSRF-Token header. The token is returned in the login response and must be included in subsequent requests.

Database Information

CaddyMAN uses SQLite for data storage, providing reliability and ease of backup.

Database Location

All configuration is stored in: CaddyMAN.db

Database Tables

  • users: User accounts, passwords (hashed), and 2FA settings
  • settings: Application configuration (key-value pairs)
  • groups: Access control groups
  • websites: Static website configurations
  • reverse_proxies: Reverse proxy configurations

Backup & Restore

  • Backup: Simply copy CaddyMAN.db to a safe location
  • Restore: Stop CaddyMAN, replace the database file, then restart
  • Automated: Consider setting up scheduled backups of the database file
